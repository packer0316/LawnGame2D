## 尺寸與戰鬥空間

- 使用現有 16px 格子；主平台至少寬 288px，總長超過所有懸空平台長度的 80%。
- 中層與最高地面保留 128px，上層與中層也間隔 128px；給角色、怪物與招式留下垂直空間。
- 層距高於目前單次跳躍極限，所有主平台皆提供繩梯。寬度至少 30 格的主平台設兩個上下通道。
- 主平台採單向足場，可向下跳；小平台作短距離銜接。以實際物理產生的導航圖驗證所有足場可達。
- 主戰鬥區保留左右各一格的生怪緩衝，小踏台不單獨設生怪區，讓怪物主要分布在寬平台上。
- 每房上層生怪總預算為 `floor(地圖格寬 / 6)`，按主平台長度分配；地面仍使用原有的同一公式。寬平台不直接套用原先「每三格加一隻」的算法。
- 地面採六種完整的階地輪廓，至少 64px 高低差；高地、谷地間用連續 16px 斜坡連接，取代隨機小凸塊。兩端入口、出口保留同高平地。
- 各主平台補上少量現有主題裝飾，沿台緣放置並避開繩梯出口。
- 沿用主題、房間尺寸及房間連接規則；沒有設定大範圍技能的判定或傷害數值。

## 修改與重建

版型來源：[src/platformLayouts.ts](src/platformLayouts.ts)。房間組裝、生怪區與繩梯：[src/rooms.ts](src/rooms.ts)。正式資料為根目錄 `content/maps/map_0001.json` 至 `map_0020.json`；編輯來源為 `editor/fixtures/ldtk-verdant/world.ldtk`。

在 `editor/` 執行：

```powershell
npm run fixtures -- --profile verdant --tilesets-from ../content/tilesets
npm run ldtk-convert -- --in editor/fixtures/ldtk-verdant/world.ldtk
```

第一步會重建 LDtk 房間；如果之後已用編輯器手動改圖，需先整合那些修改再重建。遊戲的 `?content=dev` 使用另一套測試地圖，本次更新對象是預設正式 `content/`。
