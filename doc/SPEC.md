## 0. 名詞

| 名詞 | 定義 |
|---|---|
| 一刀 | 一段攻擊判定。普攻每按一次是一刀；技能有幾段就是幾刀 |
| 押注 B | 玩家選定的單位押注，相當於魚機的砲台倍數。每一刀命中扣一次 B |
| 倍率 M | 怪物的派彩倍率；擊殺派彩 = `B × M` |
| RTP | 理論返還率（例：96%） |
| 房間（Room） | 一張地圖 = 一個房間，每種場景 1 間，共 9 間；房間 id 沿用地圖編號（1、4、5、8、9、10、15、16、17） |
| 怪潮 | 相當於魚機的魚潮：定時湧入大量低倍率怪物的時段 |
| 足場（Foothold） | 楓之谷式地形：由線段組成的可站立地面／平台／牆 |
| 繩梯（Climbable） | 繩索、梯子 |
| 角色（Avatar） | 四職業共用的固定人物 + 依職業替換的武器 |
| 錨點 | 人物每幀標記的位置（head、torso、hand）；武器對齊 hand，特效從 hand 發射 |
| Tag／Slice | Aseprite 的動畫標籤與區域標記；Tag = 一個動作，Slice = 錨點或判定框 |
| 頓幀（Hit-stop） | 命中瞬間整個畫面停頓數十毫秒，用來加強打擊感 |
| 掛機（Auto） | 自動移動、選怪、攻擊、（可選）換房 |
| LocalServer | Demo 用、在瀏覽器裡執行的假伺服器，負責扣款、擊殺判定、生怪 |

## 1. 技術選型（像素風、純網頁）

### 1.1 結論

| 部分 | 選擇 |
|---|---|
| 引擎 | **Phaser 4（≥ 4.2）+ TypeScript + Vite** |
| 像素繪圖與動畫 | **Aseprite**：用 Tag 分動作、用 Slice 標錨點與判定框；以 CLI 批次匯出 sprite sheet + JSON。原畫可手繪，也可用 AI 產生後整理（目前的測試美術就是這樣，見 `game/assets/verdant/`） |
| 動態光影 | Phaser 4 內建動態光照（物件 `setLighting(true)`）+ 法線貼圖；Bloom 用 Phaser 4 的濾鏡組合 |
| 法線貼圖 | **Laigter** 從手繪圖自動產生，再手動修整 |
| 地圖繪製 | **LDtk**：用格子畫碰撞、依規則自動拼貼地形圖塊、擺放傳送點／生怪區／光源；20 房放在同一個專案 |
| 造型製作系統 | Vite + React，預覽畫布直接共用遊戲的 Phaser 場景（見 [STUDIO_SPEC.md](STUDIO_SPEC.md)） |
| 遊戲 UI | HUD 與面板用 HTML/CSS（React）疊在畫布上，使用像素字型與像素九宮格邊框 |
| 字型 | 繁中像素字型 **Fusion Pixel 12px TC**（備選：俐方體11號）；傷害數字用 Aseprite 自繪的點陣字 |
| 伺服器 | Demo 不架伺服器：瀏覽器內的 LocalServer 模擬，介面與正式版相同；正式版再換成 Node.js + Colyseus |
| 專案結構 | npm／pnpm workspace monorepo |
| 部署 | 靜態網站 |

### 1.2 為什麼這樣選

**Aseprite：像素美術的業界標準**

- 2026 年各家像素工具評比幾乎都把 Aseprite 當首選：時間軸、洋蔥皮、圖層、Tag、Slice 一應俱全。
- CLI 可以批次匯出：`--split-layers` 把每個圖層匯出成獨立的圖，`--list-tags`、`--list-slices` 把動作與錨點寫進 JSON。
- Slice 可以逐幀設定位置與 pivot，剛好拿來標角色的錨點（武器握點）與怪物的判定框。

**Phaser 4：網頁 2D 遊戲框架中，像素風與光影支援最完整**

- 官方有 Phaser 4 像素風指南：`pixelArt`、`smoothPixelArt`、`roundPixels` 等設定，處理好縮放與鏡頭移動的抖動。
- 內建 Aseprite 載入：`load.aseprite()` 加上 `anims.createFromAseprite()`，每個 Tag 直接變成可播放的動畫。
- 2026 年加入動態光照：任何物件呼叫 `setLighting(true)` 就會受光，可搭配法線貼圖與自陰影。Dead Cells 的光影氛圍就靠這個。
- 內建濾鏡（Glow、Blur、Threshold、ParallelFilters）可組成 Bloom 發光效果。
- 內建鏡頭跟隨、震動、淡入淡出、Tilemap、鍵盤／觸控／手把輸入、音效、粒子、補間。

**LDtk：像素平台遊戲最方便的關卡編輯器**

- 由《Dead Cells》開發者製作，免費開源。
- 自動拼貼（auto-tiling）比 Tiled 好用很多：在格子上畫出「哪裡是地面」，地形的邊角、草皮、土壁就會依規則自動拼好。
- 支援自訂實體與欄位（傳送點、生怪區、光源），一個專案可放多個關卡。
- 輸出 JSON。由我們的轉換工具轉成遊戲用的地圖格式，遊戲本身不依賴 LDtk。

### 1.3 其他選項

| 選項 | 適合 | 不選的原因 | 結論 |
|---|---|---|---|
| **Phaser 4** | 網頁像素風 2D | — | ✅ |
| PixiJS 8 | 純渲染、高度客製 | 像素取整、鏡頭、Aseprite 動畫、光照都要自己做 | 次選 |
| Godot 4.7 | 像素風獨立遊戲 | 網頁版包體大、載入慢 | 若改做 App 再考慮 |
| 3D 轉像素（Dead Cells 的做法） | 動畫最流暢、換裝不用逐幀畫 | 需要 3D 建模與動畫能力，手繪味較少 | 不採用（已決定全部手繪） |
| Spine | 骨架動畫 | 旋轉與變形會破壞像素格線 | ✗ |

### 1.4 美術工具與授權

| 用途 | 工具 | 費用／授權 |
|---|---|---|
| 像素繪圖、動畫、匯出 | Aseprite | 約 US$20 一次買斷；也可依官方授權自行編譯原始碼 |
| 法線貼圖 | Laigter | 免費（自由付費），GPL 開源；有像素風模式 |
| 地圖 | LDtk | 免費開源 |
| 繁中像素字型 | Fusion Pixel 12px TC、俐方體11號 | SIL OFL，可商用（使用前確認字型包內的授權檔） |
| AI 輔助（選用） | AI 像素工具產生草稿 → Aseprite 手動修整 | 確認各工具的商用授權 |

- 楓之谷與 Dead Cells 的素材都有版權。「像」指的是風格與手感，素材一律自製或使用可商用素材。
- Phaser、React、Vite、LDtk 皆為免費開源授權。

## 2. 遊戲概述

### 2.1 設計三支柱（依優先順序）

1. **博奕核心 = 魚機。** 一刀一注、怪物倍率、機率擊殺、RTP、押注控制。任何表現層設計都不能改變這套規則。
2. **楓之谷的世界。** 平台地圖、繩梯、傳送點、9 種場景各 1 房、Q 版 2.5 頭身角色、四職業（共用同一個人物、各拿各的武器）、掛機。
3. **Dead Cells 的手感。** 流暢動作、打擊感（頓幀、震動、閃白、刀光）、翻滾、動態光影。

### 2.2 魚機對照表

| 魚機 | 本作 |
|---|---|
| 砲台 | 玩家角色 |
| 發射一顆子彈 = 一注 | **砍中一刀 = 一注** |
| 砲台倍數 | 押注 B；武器光效隨押注等級變化 |
| 魚 | 怪物 |
| 魚的倍率 | 怪物倍率（頭上顯示） |
| 子彈打中魚 → 機率擊殺 | 刀打中怪 → 機率擊殺 |
| 範圍彈一發打到多隻魚 | 一刀砍到多隻怪：仍只扣一注，分攤給所有被砍中的怪 |
| 子彈會反彈直到打中 | 揮空不扣款（魚機的子彈幾乎一定打得到東西） |
| 自動射擊、鎖定 | 掛機、鎖定目標 |
| 特殊魚（炸彈、閃電） | 特殊怪 |
| 魚潮 | 怪潮 |
| Boss 魚 | Boss |
| 換桌 | 換房 |

### 2.3 基本規格

| 項目 | 規格 |
|---|---|
| 類型 | 2D 橫向卷軸、割草包裝的魚機 |
| 美術風格 | 「森境：晨光魔法森林」像素風：深青綠環境、霧金介面、栗髮綠斗篷的旅人（Q 版 2.5 頭身）、輪廓鮮明的森林怪物。三個主題（晨光森林、螢苔洞窟、月影遺跡）有亮有暗，暗場景用光源營造 Dead Cells 式氛圍；特效高飽和並且會發光 |
| 視角 | 楓之谷式側視：多層平台、斜坡、繩梯、傳送點 |
| 平台 | 網頁：桌機 Chrome／Edge／Safari、手機瀏覽器 |
| 解析度 | 內部高度 540 像素、寬度隨螢幕比例（16:9 為 960）；詳見 §4.1 |
| 操作 | 玩家手動操作／自動掛機，可隨時切換 |
| 地圖 | 9 個房間（每種場景 1 間）；靠傳送點前往下一房，或點左上角「換房」直接選房 |
| 職業 | 劍士、法師、弓箭手、刺客 |
| 玩家生死 | 玩家沒有血量、不會死亡；怪物不攻擊玩家 |

- **手機：** 左下虛擬搖桿，右下按鈕。只在觸控裝置顯示。
- **HUD 風格：** 像素九宮格邊框（CSS `border-image` + `image-rendering: pixelated`）、像素字型，UI 依整數倍縮放。

## 3. 核心玩法

### 3.1 一刀一注（博奕核心）

**扣款規則**

- **每一刀命中至少一隻怪，扣一次押注 B。**
- 普攻每按一次是一刀；技能有幾段就是幾刀（見 §3.3 技能表），每一段命中各扣一次。
- **揮空不扣款**：魚機的子彈幾乎一定打得到東西。如果揮空也扣錢，玩家會覺得被吃錢，實際 RTP 也會低於設計值。
- 投射物（魔法彈、箭、飛鏢）在命中時才扣款；飛出畫面都沒打到則不扣。
- 一刀砍到多隻怪仍只扣一次 B，這一注分攤給所有被砍中的怪。

**擊殺判定（Demo 由 LocalServer 執行，正式版由伺服器執行）**

一刀砍中 N 隻怪，第 i 隻倍率為 `Mᵢ`、分到的權重為 `wᵢ`（`Σwᵢ = 1`）：

```
擊殺機率  pᵢ = RTP_base × wᵢ / Mᵢ
擊殺派彩     = B × Mᵢ
期望值    E  = Σ pᵢ × B × Mᵢ = RTP_base × B     ← 每一刀的期望值永遠是 RTP × 押注
```

- **押注 B 不影響擊殺機率**，只影響派彩金額。跟魚機一樣：砲台倍數越高賠越多，但打死魚的機率不變。
- **不管單體或群攻、打大怪或小怪、用哪個職業，理論 RTP 都一樣。** 職業與技能只改變手感、速度與演出。
- 權重規則（技能設定）：`even` 平均分配；`primary50` 主目標佔 50%、其餘平分。
- 倍率最低 2×，所以 `pᵢ` 永遠 ≤ 0.5，不會出現機率超過 1 的情況。
- RTP 預算拆分範例：基礎擊殺 90% + 特殊玩法 6% = 總 RTP 96%。實際數值另立數學規格書。
- 水位、個人調控等調控層屬於正式版伺服器，Demo 不做。

**技能押注倍數（v1.1）**

普攻一刀就是一注；技能比較強、打得比較多，所以比較貴。每個技能有**價格 N**（`skills.json` 的 `price`，1–20，普攻 1、大絕招 20）：

```
一刀的押注倍數  c = (N ÷ 刀數) × min(1, 打中隻數 ÷ 滿價隻數)，並壓到每隻擊殺機率 ≤ 1
這一刀扣款         = B × c                      （揮空 c = 0，不扣）
擊殺機率        pᵢ = RTP × c × wᵢ ÷ Mᵢ          （錢拿去提高擊殺率）
擊殺派彩           = B × Mᵢ                     （派彩倍率不變）
期望值             = RTP × B × c = RTP × 實際花費
```

- **放一次技能、每一刀都打滿，最多扣 B × N**；N 平均分到每一刀。
- **打越多越貴、打不到就便宜**：一刀打中的隻數少於「滿價隻數」（`fullTargets`，一般密度下預期打中的隻數）就按比例少扣；拿 20 倍大絕招只打到一隻小怪，只會扣到「讓那隻必死」為止。打得比滿價隻數多也不多收（多打的免費）。
- **不是無腦的貴（CP 值）**：價格 N = round(預期打中隻次^0.7)，所以打得越多，**每隻次的單價越低**：普攻 1.00，一般技能約 0.4–0.6，大絕招 0.11–0.27。在任何技能下，每花一塊錢的期望返還都是 96%（公平），但貴的技能**一次殺得多、每秒殺得多**：大絕招一次約 3.3 隻、每秒約 2–3 隻，普攻一次約 0.16 隻、每秒約 0.5–0.7 隻。
- **計算方式**：`npm run prices -w @lawn/rtp-sim` 從 20 張正式地圖量出怪物密度（可站立長度上每像素 ≈ 0.0088 隻、每房 30 隻），依每個技能的範圍、刀數、位移估出「預期打中隻次」，算出價格與滿價隻數；加 `--write` 寫回 `skills.json`。改了技能範圍或地圖就重算。
- **驗證**：理論返還率（逐刀加總期望值）精確等於 96%；蒙地卡羅 10⁷–3×10⁷ 刀落在 96.1–96.3%（大絕招讓高倍率菁英更常被打死，派彩分布尾巴長，需要更多刀數才收斂）。
- **開發模式**：技能每一刀固定 1 倍（`AttackReq.flat`），方便測試；實際模式照價格。
- **正式版**：倍數由伺服器依 `skills.json` 計算（`strikeCostMultiplier`，遊戲端只用同一個公式預扣顯示）。

- **位移：** `dash` 貼地衝刺、`leap` 跳起來（不受「放開跳躍鍵降低高度」影響）、`blink` 瞬移、`chain.blink` 每一刀瞬移到目標背後；衝刺、跳躍、瞬移時留下殘影。範圍 `path` 是技能開始的位置到現在位置掃過的路線。
- **特效：** 閃電、隕石、岩刺、冰環、箭雨、刀光等用程式繪製（`engine/src/feel/SkillFx.ts`），可再換成美術特效；名稱寫在每一刀的 `fx` 與 `cues`。
- **大絕招（金框）：** 範圍是整張地圖（`area.shape = 'map'`），價格 ×20（§3.1 技能押注倍數）：花 20 倍押注，擊殺率也乘上去，一次約殺 3 隻以上，RTP 不變。
- 職業可隨時在 HUD 切換（待確認，見 §11）。

**開發模式與實際模式**

| | 開發模式 | 實際模式（預設） |
|---|---|---|
| 普攻 `1` | ✓ | ✓ |
| 技能列 `2`–`9` | 固定放該職業所有技能，冷卻好就能按；**每一刀只算 1 倍押注**（測試用） | 一樣固定、有冷卻；**每個技能照價格扣押注倍數**（格子右上角 ×N，§3.1） |
| 自動冒險 | 冷卻好就放 | 冷卻好就放（照 §3.6 的時機） |

- 技能價格、滿價隻數與計算方式見 §3.1「技能押注倍數」。

### 3.4 戰鬥手感（Dead Cells）

| 項目 | 規格 |
|---|---|
| 出招速度 | 按下攻擊到第一次判定 ≤ 3 幀（50ms）：預備動作短、收招長 |
| 動作取消 | 收招階段可以用翻滾、跳躍或下一段連擊取消 |
| 輸入緩衝 | 150ms：動作中提前按的下一個指令，會在可取消時立刻執行 |
| 土狼時間 | 離開平台邊緣後 80ms 內仍可起跳 |
| 跳躍緩衝 | 落地前 100ms 內按跳，一落地就起跳 |
| 翻滾 | 0.35 秒、前衝 100px、可穿過怪物、可被攻擊取消、冷卻 0.6 秒。動作設計成「壓低身體向前滑衝」，頭部保持正立（避免頭髮、帽子要多畫旋轉圖） |
| 頓幀 | 普攻命中 30ms、技能命中 60ms、擊殺 ≥ 50× 的怪 100ms；同一刀打到多隻不疊加 |
| 鏡頭 | 命中微震 1–2px；大招、擊殺 Boss 大震；攻擊時鏡頭朝攻擊方向微推 |
| 受擊回饋 | 怪物閃白 1 幀、擊退、火花或碎片粒子 |
| 刀光 | 每一刀都有刀光特效，顏色與大小依押注等級（§3.2） |
| 遠程瞄準 | 投射物出手時，在面向 ±θ、射程內找角度偏差最小（其次最近）的怪並朝它飛；追蹤型飛行中每秒最多轉 N 度，目標死掉就沿當下方向直飛。不被地形擋（楓之谷式）。θ、射程、轉向速度寫在技能的 `projectile.aim`；手動與掛機同一套 |
| 落地 | 塵土粒子 + 1 幀壓扁姿勢 |
| 大擊殺 | 擊殺 ≥ 100× 的怪：慢動作 0.3 秒 + 光暈爆發 + 金幣爆量 |
| 音效 | **多層疊加**：一個事件由好幾層真實素材依時間差疊起來（例：隕石術 = 蓄力 → 火球呼嘯 → 爆炸＋低頻爆裂＋加農砲＋火焰＋餘震）。事件：起手、每一刀揮出、技能特效（雷擊、地裂、冰爆…，沒打到怪也響）、演出時點（隕石落下、箭射上天）、投射物射出、命中（技能或職業的打擊聲；力道大再疊重擊、一次打 5 隻以上再疊群體打擊）、技能位移、跳躍落地翻滾、擊殺（倍率 ≥ 10 加金幣爆出）、金幣噴出、撿到金幣（固定音高一聲，不做音階）、大獎、換房、押注、切換職業、自動冒險、HUD 按鈕點擊與滑過。武器、卷軸掉落與撿到都不出聲（使用者覺得吵）。左右聲道跟著鏡頭，畫面外的小聲；同一素材 25ms 內不重複觸發、最多 48 個聲音同時響、總輸出過壓縮器不爆音。設定面板有音效音量（存 localStorage）。素材全部 CC0（Kenney、OpenGameArt、freesound），`game/scripts/build-sfx.py` 下載、裁切、正規化成 `game/assets/sfx/*.mp3` 並產生來源清單 `CREDITS.md`；組合表在 `engine/src/audio/sfxCues.ts` |

- 頓幀與慢動作只是演出，不改變攻速上限與扣款規則。瞄準只提高命中率，扣款與擊殺機率公式不變（§3.1）。
- 所有數值集中在 `game/shared/src/feel.ts`，可在遊戲內除錯面板即時調整。

### 3.5 移動與物理（楓之谷式足場物理）

不使用 Phaser 內建物理，自寫足場物理，放在 `game/shared`（遊戲與編輯器共用）。

- 沿足場線段跑動，支援 45° 斜坡；垂直線段視為牆。
- 跳躍：重力、最大落速、空中可左右控制（比楓之谷靈活，接近 Dead Cells）。
- 下跳：`↓ + 跳` 穿過單向平台，最底層地面不可穿。
- 繩梯：`↑` `↓` 攀爬，可從繩上左右跳出。
- 翻滾、土狼時間、跳躍緩衝見 §3.4。
- 碰到怪物不受傷、不擊退。
- 固定時間步長（60Hz）更新物理，畫面插值顯示，不受螢幕更新率影響。
- 物理常數集中在 `game/shared/src/physics/constants.ts`。

### 3.6 自動掛機

**狀態機**

```
        ┌─────────── 目標死亡／消失 ──────────┐
        ▼                                    │
 [選目標] ──→ [尋路] ──→ [進入射程] ──→ [攻擊] ┘
    │ 本房怪物不足（且開啟自動換房）
    ▼
 [前往傳送點] ──→ [進入下一房]
```

| 設定 | 選項 |
|---|---|
| 選怪策略 | 最近／最高倍率／最密集；鎖定指定怪種（Demo 後） |
| 技能 | 冷卻好就自動放（開／關）；**貴的先放**（價格 ×N 高的優先，§3.1）；群攻技能要射程內有 2 隻以上，或目標是菁英／Boss 才放 |
| 自動換房 | 開／關；條件：本房走得到的怪少於 3 隻持續 8 秒（Demo 先固定，之後開放設定），走去「下一房」傳送點按 ↑ |
| 停止條件 | 餘額低於 X／本次累計輸 ≥ X／本次累計贏 ≥ X／單次派彩 ≥ X 倍／時間到 |
| 手動介入 | 按任何移動或攻擊鍵就暫停自動，放開 3 秒後恢復（秒數可設） |
| 掛機收益 | 操作列上緣、「自動冒險／冒險中」按鈕正上方的按鈕（操作列換成兩排時在整條操作列上面）：掛機中顯示「已掛機 10:39 +輸贏」（綠燈），停止後顯示「上次掛機」；點開的面板從按鈕往上展開：掛機時間、輸贏、起始／目前／最高／最低財產；**財產變化折線圖**可切時間級距（1分／5分／15分／1時／全部，看最近一段時 Y 軸以那段的高低為準），滑過看時間與財產，按放大鈕或點圖開大圖（同樣可切級距，另顯示此區間輸贏）；**獲得的裝備與卷軸**前面放物品圖（武器用背包圖格、卷軸用卷軸圖），同樣的合併成 ×N，顯示最近一次的時間，滑過看每次時間。曲線 6 小時內每秒一點，畫圖時依寬度抽樣並保留高低點。停止後保留到下次開始掛機，存在瀏覽器（重新整理還看得到；掛機中關掉頁面就當成在最後一點停止）。改金錢、清空重置時整條曲線平移，不算輸贏 |

- **尋路：** 地圖帶有導航圖（節點 = 平台段，邊 = 跑／跳／下跳／繩梯／翻滾／傳送點），用 Dijkstra 搜尋（圖很小，不需要 A* 的啟發函數）。導航圖由工具產生（見 [STUDIO_SPEC.md §6.3](STUDIO_SPEC.md#63-工具功能)）；地圖沒有導航圖時遊戲會現場產生。
- **執行：** 掛機輸出跟鍵盤相同的輸入（走到邊的起跳點、停穩、照模擬時的按法跳／下跳／爬），所以掛機遵守同一套物理。落點不對或 6 秒沒走完就重新規劃；打不到的目標 5 秒內不再選。
- **高處的怪：** 跳得到就跳起來打；頭上有單向平台時不跳（會落在平台上）。
- **先打這一層：** 選目標時先看這一層（高低差 40 以內）走得到的怪；**有 2 隻以上就只在這層選**，只剩 1 隻或沒有了才走去別層。
- **換層技能（昇龍斬、瞬移術、影襲）：** 目標在別層就直接用技能斜著過去；另外會主動換層：技能好了、這層沒有密集區且別層至少 2 隻、不少於這層的 8 成，或在同一層待超過 8 秒（別層至少 2 隻），就換過去，不會一直停在同一層。剛到一層至少待 1.5 秒才會再主動換層，避免來回彈。
- **技能換層後留在新的一層：** 落地（腳下高度變了）就立刻重新選目標，不會拿舊目標跑回原來那層；是技能帶過去的（含影襲的連鎖瞬移），**6 秒內只要這層還有怪就留在這層打**。昇龍斬、瞬移術只在換層時放，打怪時不拿來當攻擊技能（不然會被帶去怪最多的那層）。
- 掛機只對射程內有怪的方向出招，所以掛機幾乎不會揮空。
- **公平：** 手動與自動套用同一個攻速上限，掛機沒有速度優勢。
- **分頁切到背景：** 掛機暫停，回來時繼續。

### 3.7 房間與換房

| 項目 | 規格 |
|---|---|
| 數量 | 9 房，每種場景 1 房、每房一張地圖，主題與怪物組成不同 |
| 房間設定 | 名稱、地圖、押注範圍、怪物組成、Boss、怪潮、BGM（`rooms.json`） |
| 傳送點 | 每房有「下一房」（i → i+1，20 → 1 環狀）與「上一房」（i → i−1，1 → 20）；走到傳送點按 `↑` 進入，掛機時自動進入 |
| 換房按鈕 | 左上角「換房」打開房間列表：20 格，每格顯示縮圖、名稱、怪物圖示、押注範圍；目前房間高亮；點選 → 確認 → 切換 |
| 冷卻 | 換房冷卻 2 秒，防連點 |
| 預載 | 進房後在背景預載相鄰兩房的資源，讓走傳送點的轉場幾乎無等待 |

**換房流程**

```
遊戲                                  LocalServer（正式版：伺服器）
  │── changeRoom {toRoomId, via} ──→  │ 1. 結算所有未回覆的攻擊
  │                                   │ 2. 離開舊房、建立新房怪物
  │ ←── roomChanged + snapshot ────── │
  │ 鏡頭淡出 → 載入地圖（已預載則跳過）→ 在對應傳送點出現 → 鏡頭淡入
```

### 3.8 怪物

**等級與特殊玩法**

| 等級 | 倍率範圍 | 說明 |
|---|---|---|
| 一般 | 2× – 20× | 房間主力，數量最多 |
| 菁英 | 30× – 80× | 體型較大、有演出用血條 |
| 特殊 | 依玩法 | Demo 只做炸彈怪：死亡時對範圍內怪物各做一次免費判定。之後可加閃電、鑽頭、寶箱 |
| Boss | 100× – 500× | 每房定時出現、有登場演出 |

特殊玩法的期望值要計入總 RTP 預算。

**演出規則**

- 傷害數字是純演出：依職業傷害區間隨機顯示，跟判定無關。
- 一般怪不顯示血條，只顯示倍率標籤。
- 菁英／Boss 的血條依命中次數遞減；未判定擊殺前最低停在 10%，避免「明明沒血卻不死」的挫折感。
- 大獎等級（派彩 ÷ 押注）：Big Win ≥ 50×、Mega Win ≥ 100×、Super Win ≥ 300×，門檻可調。

**怪潮（對應魚潮）**

- 每房每 5–8 分鐘一次，持續 30–45 秒。
- 開始前 3 秒顯示警告橫幅並切換音樂；大量低倍率怪物從地圖一側沿平台湧入，房間怪物上限暫時提高到 150。
- 怪潮是割草爽感的高峰，群攻技能在這時最有用。
- 怪潮不改變 RTP，只改變怪物數量與節奏。

**動作：** 必備四個動作 `move`（移動）、`idle`（待機）、`hit`（受擊）、`die`（死亡），Boss 可加 `appear`（登場）。幀數與美術規格見 [STUDIO_SPEC.md §5.1](STUDIO_SPEC.md#51-美術規格)。

- `hit`：被命中但未死時播放，播完回到 idle／move；閃白由程式處理。
- `die`：播完淡出；噴金幣的時機由工具設定。
- 一般怪的出生／消失用程式做淡入淡出，不需要動畫。

**行為**

- 移動類型：地面巡邏（在所屬平台範圍內來回，走到邊緣轉身，隨機停下 idle）／飛行（範圍內漂浮）／靜止。
- 循環：idle（隨機 1–3 秒）→ move（隨機 2–5 秒）→ …；受擊會打斷並擊退。
- 生成：依地圖的生怪區維持數量上限，死亡後 N 秒補怪。單房怪物上限初定 80（怪潮時 150）。
- **確定性 AI：** 怪物位置由「亂數種子 + 生成時間」推算，之後做多人同房時每台看到的位置會一致。

## 4. 美術規格（像素風）

### 4.1 解析度與像素規範

| 項目 | 規格 |
|---|---|
| 內部解析度 | 高 540 像素；寬隨螢幕比例（16:9 = 960，21:9 ≈ 1260） |
| 縮放方式 | 畫布以裝置實際像素渲染，鏡頭縮放 = 螢幕高 ÷ 540，開啟 Phaser `smoothPixelArt`：任意倍數下像素都銳利，鏡頭可平滑移動。1080p 螢幕剛好 2 倍。比例固定，不為了填滿畫面而放大 |
| 地圖寬度 | **滿版且看得到頭尾**：每房固定 1440（90 格）。一般寬螢幕扣掉 HUD 後畫面約 1440–1500 內部像素寬，整張地圖剛好在一個畫面內、兩端傳送點都看得到；不做比畫面窄的小地圖，也不做要捲動的大地圖 |
| 備案 | 若 M0 發現畫質或效能不佳，改用 `pixelArt` + 整數倍縮放 |
| 地圖格子 | 16×16 |
| 角色 | 楓之谷式 Q 版 2.5 頭身，身高約 56–64 像素，頭部佔身高約 45% |
| 怪物尺寸 | 一般 24–48、菁英 64–96、Boss 128–192 像素高 |
| 描邊 | 1 像素深色描邊，用同色系深色，不用純黑 |
| 旋轉 | 角色與怪物不旋轉，只做水平翻轉；特效、金幣、碎片可旋轉 |
| 原點 | 角色與怪物的原點一律在腳底中心 |

**流暢感的三個來源：**

1. 角色與怪物的動畫幀數比楓之谷多（[STUDIO_SPEC.md](STUDIO_SPEC.md) §4.2、§5.1）。
2. 通用特效層：刀光、殘影、塵土、火花，不綁在角色或武器上。
3. 程式演出：頓幀、擊退、震動、閃白、慢動作（§3.4）。

### 4.2 光影（Dead Cells 式氛圍）

| 項目 | 規格 |
|---|---|
| 環境光 | 每套主題設定環境光的顏色與亮度。例：森林白天偏亮、洞窟偏暗、廢墟夜晚帶藍紫月光 |
| 地圖光源 | LDtk 的 `Light` 實體：顏色、半徑、強度、閃爍（火把、燈籠、發光晶石） |
| 動態光源 | 技能、投射物、金幣、傳送點自帶短暫光源；玩家身上一盞柔光，亮度隨押注等級提高 |
| 法線貼圖 | 地形 tileset、背景、大型裝飾用 Laigter 自動產生再手修，讓光照出立體感。角色與怪物在 Demo 不做法線貼圖 |
| 角色與怪物受光 | 開啟 `setLighting(true)`，不帶法線貼圖時只受明暗與顏色影響，進入暗處會自然變暗 |
| 發光 | 技能特效、金幣、高倍率標籤用加色混合，再加輕微 Bloom（Phaser 4 以 ParallelFilters + Threshold + Blur 組成） |
| 畫質設定 | 高：動態光照 + 法線 + Bloom。低：關閉光照，改用依主題的固定色調。手機預設依 M0 量測結果決定 |

> 注意：物件開啟光照會改用另一個著色器，打斷合批。只對需要的圖層開，M0 必須量測 80 隻怪全開光照時的效能。若太重，備案是怪物不開光照，改用「依最近光源計算的色調」模擬。

### 4.3 角色與武器

**同一人物、武器與套服獨立換裝：** 四個職業共用森境旅人的臉型與身形；切換職業時換成該職業的武器（`ClassDef.weapon`），保留目前套服。行囊提供全職業共用「套服」欄位，可獨立選擇「蒼影忍裝」與兜帽半遮臉的「白隼刺客服」。現有與新存檔直接提供；舊存檔補入新套服時保留目前裝備，卸下即恢復原裝。套服只改外觀，不改技能時序、數值或碰撞；不佔武器背包格、不參與武器出售與衝卷。每套均包含原有 15 組／67 格基礎動作及 12 組／96 格技能動作，素材與紀錄見 [忍裝美術包](../game/assets/outfits/ninja/README.md)、[白隼刺客服美術包](../game/assets/outfits/hood/README.md)。美術製作規格（角色檔、錨點、武器製作）與工具功能見 [STUDIO_SPEC.md §4](STUDIO_SPEC.md#4-角色與武器)。本節只描述遊戲執行時的行為。

| 項目 | 規格 |
|---|---|
| 人物 | `content/avatar/base`：15 個動作、67 幀，`body` 圖層（必要），`arm_front` 圖層（選用，要蓋在武器握把上時才畫） |
| 錨點 | `hand`（武器握點、投射物與施法特效的發射點）、`torso`（背後武器的對齊點）、`head`（特效與標籤） |
| 武器 | 每個職業一把：`weapon` 圖層畫在人物前面，`weapon_back`（例如箭袋）畫在人物後面；爬繩梯時收起武器（不畫） |
| 圖層順序 | 由後到前：`weapon_back` → `body` → `weapon` → `arm_front` |

**執行時組裝**

- 用 Phaser Container 依圖層順序疊 Sprite，每幀的擺放由 `@lawn/shared` 的 `composeAvatarFrame` 計算（編輯器的工具畫面用同一套）。
- 武器只畫姿勢幀時，中間幀沿用最接近的姿勢並跟著 `hand` 錨點位移；每幀都畫時直接用同一幀。
- 整個 Container 以 `scaleX = -1` 做左右翻轉。
- 押注等級外觀（§3.2）是疊在武器上的光效與刀光，不改武器本身的圖。

### 4.6 演出

| 項目 | 做法 |
|---|---|
| 傷害數字 | Aseprite 繪製的點陣數字（楓之谷式橘色，暴擊另一種顏色），往上疊、最後一段放大 |
| 擊殺 | `die` 動畫 + 爆散粒子 + 閃光 → 金幣噴出（會發光的像素金幣），有掉武器、卷軸時一起噴出（底下有光暈；武器圖示最長邊 40px、斜 45 度）→ **落到地板、浮起來上下飄 1–1.5 秒**（每個隨機，不含掉落過程）→ **像被吸過去一樣加速飛到玩家身上**，碰到時閃一下 → 餘額數字滾動。純演出：錢與背包在伺服器判定擊殺時就已入帳（`AttackResult.results[].loot` 告訴畫面每隻怪掉了什麼） |
| 技能特效 | Aseprite 逐幀特效，`art/fx/{skillId}.aseprite`，Tag 為 `cast` 與 `hit`；附帶短暫光源 |
| 刀光 | 各攻擊動作一組通用刀光，`art/fx/slash_{tag}.aseprite`，顏色與大小依押注等級 |
| 背景音樂 | `content/bgm/{id}.mp3`，進房播放的曲子依序取：`rooms.json` 的 `bgm` → 景點的專屬曲子（`game/assets/landmarks/catalog.json` 的 `bgm`：九份、阿里山、富士山、京都千本鳥居、吉薩）→ 地圖的 `bgm`，循環播放；換房時舊曲淡出 0.7 秒、新曲淡入 1.2 秒，同一首不重播（新曲先載入好才換，讀不到不會中斷）。找不到檔案就改播 `bgm_forest`。瀏覽器要使用者先互動才出聲：第一次點擊或按鍵後開始播；分頁切到背景時暫停 |
| 怪潮 | 警告橫幅、畫面邊緣紅光、音樂切換（目前沒有專屬曲子，維持房間音樂） |
| 得獎紀錄 | 不做全螢幕大獎畫面。所有獲獎（擊殺獎金、掉落的裝備與卷軸）在畫面左側一行一行出現：最新的在最下面、舊的往上推，每行 4 秒後淡出，最多同時 8 行。倍率 ≥ 50／100／300 的大獎（Big／Mega／Super Win）用金／紫／青特殊色並標示；仍保留慢動作、震動與大獎音效。背包滿了撿不到武器時也以一行提醒 |
| 換房 | 鏡頭淡出淡入（Phaser 內建） |

## 5. 系統架構

### 5.1 專案結構

遊戲與編輯器分屬兩個資料夾、兩個獨立的 npm 專案，開發時不混在一起。分工與檔案歸屬見 [COLLAB.md](COLLAB.md)。

```
LawnGame2D/
├─ doc/                   規格書（SPEC.md、STUDIO_SPEC.md、COLLAB.md）
├─ game/                  遊戲（npm workspaces）
│  ├─ shared/             @lawn/shared：純邏輯（無渲染）：型別、內容 schema、Aseprite JSON 解析、足場物理、導航圖、技能範圍判定、RTP 公式、手感參數
│  ├─ engine/             @lawn/engine：Phaser 4 遊戲場景：地圖、光影、角色、怪物、戰鬥、掛機、LocalServer
│  │                      對外提供 createGame() 與預覽元件，遊戲與編輯器都用它
│  ├─ web/                遊戲網頁入口 + HUD（React）
│  └─ tools/
│     ├─ rtp-sim/         RTP 蒙地卡羅模擬
│     └─ placeholder-art/ 產生 Aseprite 匯出格式的測試美術
├─ editor/                造型製作系統 LawnStudio（見 STUDIO_SPEC.md）
├─ art/                   美術原始檔（.aseprite、.ldtk）
└─ content/               遊戲資料：編輯器寫入、遊戲讀取
```

### 5.2 遊戲模組（`game/engine`）

| 模組 | 職責 |
|---|---|
| `core/` | 遊戲迴圈（固定步長）、資源載入、事件匯流排、物件池、輸入（含輸入緩衝）、鏡頭設定 |
| `map/` | 地圖載入、圖塊層、視差背景、足場世界（碰撞查詢）、繩梯、傳送點、導航圖 |
| `light/` | 環境光、地圖光源、動態光源、Bloom、畫質切換 |
| `avatar/` | 角色組裝：人物 + 武器、錨點對齊（擺放計算在 `@lawn/shared`） |
| `actor/` | 玩家控制（輸入 → 物理 → 動畫）、翻滾、動作取消 |
| `monster/` | 怪物顯示、確定性 AI、生成與回收、怪潮 |
| `combat/` | 技能範圍判定 → 目標清單、攻擊請求／結果、傷害數字、金幣、押注等級外觀 |
| `feel/` | 頓幀、鏡頭震動、慢動作、閃白、刀光、粒子 |
| `auto/` | 掛機狀態機、選怪、路徑跟隨 |
| `room/` | 換房流程、相鄰房預載 |
| `server/` | `GameServer` 介面 + `LocalServer` 實作 |

HUD 與面板（押注、換房列表、掛機設定、職業切換、怪潮警告、大獎演出）在 `game/web`，用 React 實作，透過事件與 `engine` 溝通。

### 5.3 伺服器介面與 LocalServer

遊戲只透過 `GameServer` 介面溝通。正式版只要換掉實作（Node.js + Colyseus），遊戲端不用改。

```ts
interface GameServer {
  join(req: JoinReq): Promise<Snapshot>;
  attack(req: AttackReq): Promise<AttackResult>;
  changeRoom(req: ChangeRoomReq): Promise<Snapshot>;
  on(event: 'monsterSpawn' | 'monsterRemove' | 'feature' | 'wave' | 'balance', handler: (data: unknown) => void): void;
}
```

**LocalServer 的職責：** 虛擬幣錢包（localStorage）、擊殺判定、怪物生成與補怪、怪潮排程、攻速限制、換房結算。

> 瀏覽器內的亂數與餘額可以被玩家竄改。Demo 用虛擬幣所以可以接受；正式版的判定與錢包一定要放在伺服器。

### 5.4 主要訊息

| 方向 | 訊息 | 內容 |
|---|---|---|
| 遊戲→伺服器 | `join` | `roomId, classId, avatar` |
| 伺服器→遊戲 | `snapshot` | `roomId, serverTime, monsters[{uid, typeId, zoneId, seed, spawnTime}], balance, nextWaveAt` |
| 伺服器→遊戲 | `monsterSpawn` / `monsterRemove` | 單隻怪物增減 |
| 遊戲→伺服器 | `attack` | `seq, skillId, strike（第幾刀）, bet, targets[uid]` |
| 伺服器→遊戲 | `attackResult` | `seq, cost, results[{uid, killed, multiplier, payout, feature?}], balance` |
| 伺服器→遊戲 | `feature` | 特殊玩法觸發（Demo：炸彈怪） |
| 伺服器→遊戲 | `wave` | 怪潮預告、開始、結束 |
| 遊戲→伺服器 | `changeRoom` | `toRoomId, via: "portal" \| "menu"` |

錯誤碼：`INSUFFICIENT_BALANCE`、`RATE_LIMIT`、`BET_OUT_OF_RANGE`、`ROOM_CHANGE_COOLDOWN`。

**延遲處理：** 刀光、頓幀、傷害數字在命中瞬間立刻播放，死亡等判定結果。LocalServer 會模擬 30–100ms 延遲，讓演出時序跟正式版一致。`seq` 保證同一刀不會重複扣款。

### 5.5 多人連線（Demo：claude.ai Artifact）

同一間房（地圖）的玩家一起打同一批怪。Demo 部署在 claude.ai Artifact，沒有自己的伺服器，用平台的 `room` 能力（同時打開頁面的人互相連線）：

| 項目 | 做法 |
|---|---|
| 通道 | 平台的大廳（看這個頁面的所有人），每個人在 presence 的 `r` 標記自己在哪一間遊戲房，只和同一間的人互動（不用命名房間：只有檢視權限的人不一定能用）；換房就換 `r`。全部走每個人的 **presence**（平台替每人保存一份最新狀態，上限 4 KiB、約 10 次／秒），不用事件，所以只有檢視權限的人也能一起玩 |
| 主機 | 其中一位玩家的瀏覽器負責生怪、怪物 AI 與重生（LocalServer 一般模式）。剛進房等 1.5 秒看有沒有主機；有人宣告就聽最早宣告的，沒有就由標籤最小、已進入遊戲的人宣告。主機離開或分頁切到背景就交給下一位 |
| 怪物世界 | 主機把每隻怪的編號、種類、位置、面向、狀態、倍率、生怪區放進 presence；其他人（跟隨者）的 LocalServer 照這份增減怪物，畫面上的怪不跑 AI，平滑跟著主機的位置（離太遠直接瞬移） |
| 押注與擊殺 | 每個人自己的錢包、扣款、擊殺機率照舊在自己這裡算（RTP 不變）。跟隨者打死怪先在自己畫面派彩、死亡，再把 `[編號, 時間]` 放進 presence 等主機確認；主機移除那隻並排重生，其他人看到它死亡（沒有派彩）。兩人幾乎同時打死同一隻時兩邊都已派彩，主機只採用第一個（Demo 接受這個誤差） |
| 其他玩家 | 角色位置、面向、紙娃娃動作、技能整體動畫、職業武器、外觀武器、套服；畫面上用同一套紙娃娃畫出來並平滑內插，頭上顯示平台的使用者名稱。畫面上方顯示「線上 N 人」 |
| 其他玩家的技能特效 | 放技能時把 `[序號, 技能, 位置, 面向, 時間]` 放進 presence（留 2 秒）；別人照技能的時間表在自己的畫面重播（起手、演出時點、每一刀的特效、投射物、命中效果，命中目標用自己畫面上的怪），**半透明 50%**：畫在疊在遊戲上面的另一個場景，鏡頭跟著主鏡頭、整個場景透明，也不會動到自己的鏡頭或角色。純畫面，不扣款、不判定 |
| 權限 | 平台第一次用時會問玩家；遊戲一開始就批次問一次（房間、玩家名稱）。拒絕的人單人遊玩，畫面上方顯示「多人連線未開啟 · 點此開啟」，按下打開平台的權限面板，開啟後重新連線 |
| 限制 | 只有登入 claude.ai、能開這個 Artifact 的人（組織成員與受邀者）連得上，公開連結的訪客是單人；訊息可能掉（都送絕對狀態）；部署新版本會讓所有人重新載入。判定在玩家的瀏覽器裡，可以被竄改，正式版要換成真的伺服器（`GameServer` 介面不變） |
| 本機測試 | 網址加 `?net=local`：同一個瀏覽器的分頁之間用 BroadcastChannel 模擬 |

## 7. 資料格式

正式定義以 `game/shared` 的 zod schema 為準，以下為示意。工具產出的內容資料格式（部件、調色盤、怪物、地圖、主題、房間）見 [STUDIO_SPEC.md §9](STUDIO_SPEC.md#9-資料格式)。

```ts
type ClassId = 'warrior' | 'mage' | 'archer' | 'assassin';

interface SkillDef {
  id: string;
  classId: ClassId;
  kind: 'basic' | 'active';
  pose: string;                 // 角色動作 Tag，例如 'swing1'、'cast'
  strikes: {                    // 每一刀 = 一次判定 = 命中時扣一注
    atMs: number;               // 動作開始後第幾毫秒判定
    area: { shape: 'rect' | 'circle' | 'sector' | 'line' | 'screen'; w?: number; h?: number; r?: number; offsetX?: number };
    maxTargets: number;
    pierce: boolean;            // false = 只打第一隻
    weightRule: 'even' | 'primary50';
  }[];
  cooldownSec: number;
  cancelFromMs: number;         // 從第幾毫秒起可被取消
  hitStopMs: number;
  shake: number;
  fx?: string;
  slashFx?: string;
  sound?: string;
}

interface BetLevel {
  bet: number;
  visualTier: 1 | 2 | 3 | 4 | 5;   // 押注等級外觀
}
```

## 11. 待確認問題

1. **揮空要不要扣款？** 目前規則是「砍中才扣」，跟魚機子彈一定打得到東西的體驗一致。若改成「揮刀就扣」，揮空的錢會直接損失，實際 RTP 會低於設計值。
2. **技能的扣款方式：** 目前是「技能有幾刀就最多扣幾注」（例如旋風斬 3 刀 = 最多 3 注）。還是希望每個招式不論幾段都只扣一注？
